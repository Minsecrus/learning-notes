# Network Design Principles：Two-Tier、Three-Tier 与 Spine-Leaf

这几个概念说的是 **Network Architecture**，也就是网络设备如何分层、如何连接、流量通常怎么走。

可以先用一句话区分：

```text
Two-Tier：两层网络，简单直接
Three-Tier：三层网络，传统企业园区常见
Spine-Leaf：面向数据中心的横向扩展网络
```

## Two-Tier 是什么

`Two-Tier Architecture` 是两层网络架构，通常分成：

```text
Core / Distribution 层
  ↑
Access 层
  ↑
终端设备
```

或者在小型网络中，可以理解为：

```text
上层交换机 / 路由设备
  ↑
接入交换机
  ↑
电脑、服务器、打印机、AP
```

`Access layer` 负责接入终端设备，比如电脑、服务器、无线 AP。上层设备负责更集中的转发、路由、策略和连接外部网络。

Two-Tier 的特点是结构简单、设备少、成本较低，适合小型办公室、小型园区、小规模数据中心。缺点是规模变大后，上层设备容易成为瓶颈，故障影响范围也可能更大。

## Three-Tier 是什么

`Three-Tier Architecture` 是传统网络设计里很经典的三层架构，通常分成：

```text
Core 层
  ↑
Distribution 层
  ↑
Access 层
  ↑
终端设备
```

三层分别负责不同职责：

| 层级 | 主要职责 |
| --- | --- |
| Access | 接入终端设备，比如用户电脑、电话、AP、服务器 |
| Distribution | 汇聚多个 Access 交换机，做路由、ACL、安全策略、VLAN 汇聚 |
| Core | 高速骨干，负责在不同区域之间快速转发流量 |

可以把它想象成一栋大楼或校园网络：

```text
楼层里的设备 -> 楼层交换机 -> 楼宇/区域汇聚 -> 校园核心网络
```

Three-Tier 的优点是职责清晰，适合大型企业园区和传统校园网络。缺点是层级较多，路径可能更长，东西向流量效率不一定高。

这里的 `东西向流量` 指数据中心内部服务器之间的通信；`南北向流量` 指用户或外部网络访问服务器的通信。

## Spine-Leaf 是什么

`Spine-Leaf Architecture` 是现代数据中心常见的网络架构，通常分成：

```text
Spine 层
  ↕ ↕ ↕
Leaf 层
  ↑ ↑ ↑
服务器 / 存储 / 虚拟化平台
```

它的核心规则是：

> 每个 Leaf 都连接到所有 Spine；Leaf 之间通常不直接相连；Spine 之间通常也不直接相连。

这会形成一种非常规整的网状结构：

```text
        Spine 1     Spine 2     Spine 3
          |  \       |  \       |  \
          |   \      |   \      |   \
        Leaf 1     Leaf 2     Leaf 3
          |          |          |
       服务器组     服务器组     服务器组
```

任意两个 Leaf 下面的服务器通信时，路径通常是：

```text
Server A -> Leaf A -> Spine -> Leaf B -> Server B
```

所以 Leaf 到 Leaf 之间通常只需要经过一个 Spine，中间跳数比较稳定。这对数据中心很重要，因为现代应用经常是微服务、数据库、缓存、消息队列之间大量互相通信，东西向流量非常多。

Spine-Leaf 的优点是可扩展性强、路径稳定、带宽容易横向增加。比如带宽不够时，可以增加 Spine；接入服务器不够时，可以增加 Leaf。缺点是设备和链路数量较多，设计、布线和路由协议通常更复杂。

## 三者对比

| 架构 | 层数 | 常见场景 | 优点 | 局限 |
| --- | --- | --- | --- | --- |
| Two-Tier | 2 层 | 小型网络、小型数据中心 | 简单、便宜、容易管理 | 扩展性有限，上层可能成为瓶颈 |
| Three-Tier | 3 层 | 企业园区、校园网络 | 分层清晰，适合传统组织结构 | 路径较长，数据中心东西向流量效率一般 |
| Spine-Leaf | 2 层逻辑结构 | 现代数据中心、云平台、虚拟化集群 | 扩展性强，延迟和路径更稳定 | 初始复杂度和链路数量较高 |

## 一个直觉记忆

可以这样记：

```text
Two-Tier：小网络，少一层，够用就好
Three-Tier：大园区，分工明确，层层汇聚
Spine-Leaf：数据中心，服务器之间要高效互通
```

如果你看到课程或图里把它们放在 `Network Design Principles` 下面，重点通常不是让你背设备名字，而是理解：

- 网络为什么要分层
- 每一层承担什么责任
- 流量经过几跳
- 扩容时是加哪一层设备
- 这种结构适合用户访问网络，还是适合服务器之间大量互访

## 小结

Two-Tier、Three-Tier、Spine-Leaf 都是在回答同一个问题：

> 网络应该怎样组织，才能在成本、性能、可靠性和扩展性之间取得平衡？

Two-Tier 偏简单，Three-Tier 偏传统企业园区，Spine-Leaf 偏现代数据中心。
