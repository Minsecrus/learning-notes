# 游戏的 P2P 网络是如何实现的

## 核心概念

P2P（Peer-to-Peer）游戏网络的意思是：玩家设备之间直接交换游戏数据，而不是所有实时数据都必须经过一台中心游戏服务器。

但实际游戏里很少是完全没有服务器的“纯 P2P”。常见做法是：

- 服务器负责登录、匹配、房间、好友、排行榜等外围系统。
- 玩家之间尽量直接传输实时对战数据。
- 如果直连失败，再用中继服务器转发数据。

## 典型流程

1. 玩家先连接到匹配服务器。
2. 匹配服务器把玩家分到同一个房间，并交换双方的网络地址信息。
3. 客户端尝试 NAT 穿透，让两台设备直接建立 UDP 连接。
4. 连接成功后，玩家之间直接发送输入、位置、状态同步等数据。
5. 如果直连失败，就走 relay / TURN 中继服务器。

## NAT 穿透

大多数玩家都在路由器、校园网、公司网或运营商 NAT 后面，外部设备不能随便主动连进来。

所以 P2P 游戏通常需要 NAT traversal：

- 客户端先联系一个公开服务器，确认自己在公网侧看到的 IP 和端口。
- 匹配服务器把这个地址告诉其他玩家。
- 双方几乎同时向对方公网地址发 UDP 包。
- 路由器看到“我内网设备主动发过包”，就可能允许对方返回数据。

这类技术常见于 STUN / ICE 思路。WebRTC 也大量使用类似机制。

## 同步方式

P2P 游戏同步一般有两种常见思路。

### 传输入同步

每个客户端只发送玩家输入，比如“第 120 帧按下左键、释放跳跃键”。

优点：

- 数据量小。
- 所有客户端如果模拟完全一致，状态天然一致。

缺点：

- 要求游戏逻辑 deterministic，也就是相同输入必须算出完全相同结果。
- 某个玩家延迟高，可能拖慢所有人。
- 常见于 RTS、格斗游戏、一些回合或帧同步游戏。

### 传状态同步

客户端直接发送位置、速度、朝向、血量等状态。

优点：

- 实现直观。
- 对物理、随机数、浮点差异没那么敏感。

缺点：

- 数据量更大。
- 冲突处理更复杂。
- 容易被作弊客户端伪造状态。

## 主机模式

很多所谓 P2P 游戏其实是 host / listen server 模式：

- 一名玩家的设备当“房主”或临时服务器。
- 其他玩家连接到这个房主。
- 房主负责汇总状态、判定部分逻辑、转发给其他玩家。

它不是所有玩家完全平等互连，而是“玩家设备承担服务器角色”。

缺点也明显：

- 房主网络差，所有人体验都会差。
- 房主退出，房间可能中断或需要 host migration。
- 房主有作弊优势。

## 为什么现在很多游戏不用纯 P2P

主要原因是安全性和体验稳定性：

- **作弊难防**：客户端掌握太多权威状态时，很容易伪造位置、伤害、命中结果。
- **网络不稳定**：玩家网络环境复杂，NAT 类型不同，直连成功率不稳定。
- **暴露 IP**：玩家之间直连可能暴露彼此 IP。
- **一致性难做**：多人实时同步需要处理延迟、丢包、乱序、回滚和预测。

所以竞技类网游通常更偏向 dedicated server：服务器保存权威状态，客户端只提交输入。

## 一句话理解

游戏 P2P 网络通常不是“完全不要服务器”，而是：

> 用服务器做匹配和辅助连接，用 NAT 穿透让玩家尽量直连，用中继兜底；实时同步可以传输入，也可以传状态，但安全和稳定性会比中心服务器更难处理。
