# 第8章 TCP 首部总览

上一章已经算出样本 TCP 报文段从整帧偏移 34 开始。现在把坐标原点移动到 TCP 首字节：TCP 相对偏移 0 对应整帧偏移 34。借助这个局部坐标，我们可以把 42 字节 TCP 报文段准确分成 32 字节首部和 10 字节数据。

本章先建立完整布局。第9—14章会逐组深入字段语义。

## 先读原始字节，再看解析结果

样本 TCP 报文段如下，左侧偏移以 TCP 首字节为零点：

```text
TCP+00  c0 00 23 28 6a 1b 2c 3e 10 20 30 41 80 18 fa f0
TCP+10  e7 fd 00 00 01 01 08 0a 01 02 03 04 a0 b0 c0 d0
TCP+20  48 45 4c 4c 4f 20 54 43 50 0a
```

`TCP+10` 表示十六进制偏移 `0x10`，对应十进制 16。`TCP+20` 对应十进制 32，恰好是本段应用数据的起点。

TCP 首部的固定部分占 20 字节，之后可以跟随选项。首部布局可以先记成这张图：

```text
TCP 相对偏移      0                   1                   2                   3
               +-------------------+-------------------+-------------------+-------------------+
 0～3          | Source Port 16 bit                    | Destination Port 16 bit                 |
               +---------------------------------------+---------------------------------------+
 4～7          | Sequence Number 32 bit                                                        |
               +-------------------------------------------------------------------------------+
 8～11         | Acknowledgment Number 32 bit                                                   |
               +---------+-------------+---+-----------------------------------+----------------+
12～15         |DOffset 4| Reserved 3  |AE | CWR ECE URG ACK PSH RST SYN FIN  | Window 16 bit  |
               +---------+-------------+---+-----------------------------------+----------------+
16～19         | Checksum 16 bit                       | Urgent Pointer 16 bit                  |
               +---------------------------------------+---------------------------------------+
20～首部末尾   | Options 与填充，长度由 Data Offset 决定                                    |
               +-------------------------------------------------------------------------------+
首部末尾之后   | Application Data ...                                                          |
               +-------------------------------------------------------------------------------+
```

AE 使用 RFC 9768 分配的扩展标志位；未启用相应扩展的实现仍按保留位规则处理不认识的位。每个字段的原始字节范围会在下表继续展开。

## 网络字节序：先确定怎样拼接多个字节

TCP 首部中的 16 位和 32 位整数使用网络字节序，也就是高位字节在前。以源端口的两个字节 `c0 00` 为例：

$$
\begin{aligned}
0xc000
  &=0xc0\times256+0x00\\
  &=192\times256+0\\
  &=49152
\end{aligned}
$$

四字节序列号 `6a 1b 2c 3e` 同理：

$$
0x6a1b2c3e=1780165694
$$

阅读原始字节时，先按字段宽度切片，再按网络字节序组合。这样的步骤可以避免把 `c0 00` 误读成 `0x00c0`。

## 固定首部的逐项定位

| TCP 相对偏移 | 长度 | 原始字节 | 字段 | 样本值 |
| ---: | ---: | --- | --- | --- |
| 0～1 | 2 | `c0 00` | Source Port | 49152 |
| 2～3 | 2 | `23 28` | Destination Port | 9000 |
| 4～7 | 4 | `6a 1b 2c 3e` | Sequence Number | `0x6a1b2c3e` |
| 8～11 | 4 | `10 20 30 41` | Acknowledgment Number | `0x10203041` |
| 12 | 1 | `80` | Data Offset、保留/扩展控制位 | Data Offset = 8 |
| 13 | 1 | `18` | CWR～FIN 八个 Flags | ACK、PSH 置位 |
| 14～15 | 2 | `fa f0` | Window | 原始值 64240 |
| 16～17 | 2 | `e7 fd` | Checksum | `0xe7fd` |
| 18～19 | 2 | `00 00` | Urgent Pointer | 0 |

前 20 字节到此结束。它们构成每条 TCP 报文段都具有的固定首部。

端口帮助接收主机把报文交给对应的连接或监听端点；Seq 描述本方向数据在字节流中的位置；Ack 描述反方向已经连续收到的进度；Flags 表达确认、建立、关闭等控制信息；Window 公布本方向接收能力；Checksum 检查传输中的比特差错；Urgent Pointer 与 URG 控制位共同解释紧急数据位置。字段之间共同描述连接当前时刻的一小段状态。

## 用两套偏移量交叉检查

TCP 相对偏移适合查首部规范，整帧偏移适合核对 Packet Bytes。样本 TCP 起点位于整帧偏移 34，因此换算关系为：

$$
\text{Frame Offset}=34+\text{TCP Relative Offset}
$$

几个关键位置可以直接验算：

| 字段 | TCP 相对偏移 | 整帧偏移 | 首字节 |
| --- | ---: | ---: | --- |
| Source Port | 0 | 34 | `c0` |
| Sequence Number | 4 | 38 | `6a` |
| Acknowledgment Number | 8 | 42 | `10` |
| Data Offset / Flags | 12 | 46 | `80` |
| Checksum | 16 | 50 | `e7` |
| Options | 20 | 54 | `01` |
| Application Data | 32 | 66 | `48` |

若某一字段的高亮范围与手算偏移错开，先复核链路层类型、IPv4 IHL 或 IPv6 扩展首部链，再复核 TCP Data Offset。这个顺序能快速找到坐标起点上的偏差。

## 用 Data Offset 找到首部终点

TCP 相对偏移 12 的字节是 `0x80`。写成二进制：

```text
0x80 = 1000 0000
       ^^^^
       高四位 = 8
```

Data Offset 占高四位，数值单位为 32 位字，即 4 字节：

$$
8\times4\ \text{bytes}=32\ \text{bytes}
$$

所以样本 TCP 首部长度是 32 字节。固定部分已有 20 字节，选项区域长度为：

$$
32-20=12\ \text{bytes}
$$

四位二进制可以表达 `0` 到 `15`。有效 TCP 首部至少含 5 个 32 位字，最大长度由 Data Offset 的最大值给出：

$$
15\times4=60\ \text{bytes}
$$

因此 TCP 首部长度范围为 20～60 字节，选项区域最多 40 字节。样本中的 12 字节选项为：

```text
01 01 08 0a 01 02 03 04 a0 b0 c0 d0
```

它包含两个 NOP 填充字节与一个 Timestamp 选项。第14章会逐字节解析 Kind、Length 和 Value。

## 从两个长度字段算出 Payload

第7章已经读出 IPv4 Total Length 为 62 字节，IPv4 IHL 给出 20 字节 IPv4 首部。先求 TCP 报文段总长度：

$$
62-20=42\ \text{bytes}
$$

再减去 Data Offset 给出的 32 字节 TCP 首部：

$$
42-32=10\ \text{bytes}
$$

这 10 字节就是 `tcp.len`，也就是参与序列号推进的 TCP Payload 长度：

```text
48 45 4c 4c 4f 20 54 43 50 0a  ->  HELLO TCP\n
```

这里出现了两类“长度”：IP Total Length 来自 IPv4 首部字段；IP 层提供的边界与 TCP Data Offset 共同推导 TCP 报文段和 Payload 长度。

## Data Offset 与 Flags 共享相邻位区

TCP 首部布局最初按 32 位宽度绘制。Data Offset 位于第 12 字节的高四位，随后三位为保留位，该字节最低位是 AE；第 13 字节从高位到低位依次容纳 CWR、ECE、URG、ACK、PSH、RST、SYN、FIN。Wireshark 会把九个标志展开成独立字段。

样本的主要标志字节是 `0x18`：

```text
0x18 = 0001 1000
             │└─ FIN = 0
             └── SYN = 0
           1──── PSH = 1
          1───── ACK = 1
```

按照低位到高位依次对齐 FIN、SYN、RST、PSH、ACK、URG、ECE、CWR，可以得到 ACK 与 PSH 置位。第12章将用完整时间线解释这些标志的组合语义。

## 首部中的两个方向

同一条 TCP 报文段同时携带两个方向的信息：

- Source Port、Sequence Number 描述发送方当前发出的方向。
- Destination Port 指向接收端服务或已连接端点。
- Acknowledgment Number 与 Window 公布发送方对反方向字节流的接收状态。

样本由客户端发往服务端，所以 `Seq = 0x6a1b2c3e` 属于客户端到服务端的字节空间；`Ack = 0x10203041` 则指向服务端到客户端的字节空间。TCP 为两个方向分别维护序列号。观察响应报文时，源/目标端口交换，Seq 与 Ack 所属的方向也随之交换。

## 原始值、解释值与显示值

Wireshark 的字段树可能同时给出多个层次的值：

| 类型 | 样本例子 | 来源 |
| --- | --- | --- |
| 原始值 | Seq 字节 `6a 1b 2c 3e` | 抓包文件中的线上字节 |
| 协议解释值 | Data Offset `8` 代表 32 字节 | TCP 字段编码规则 |
| 上下文解释值 | Window 经 Window Scale 后的数量 | 握手协商与当前字段共同计算 |
| 便于阅读的显示值 | 相对 Seq `1` | Wireshark 显示设置 |
| 分析器推断 | 某段标记为 Retransmission | Wireshark 结合已捕获上下文判断 |

阅读时记录字段路径与原始字节，可以随时回到可复核的起点。窗口缩放、相对序列号和重传标签都会在后续章节展开。

## 一分钟首部检查清单

面对一条新的数据报文，可以按固定顺序快速自检：

1. 从 IP 层确认上层协议为 TCP，并算出 TCP 起点。
2. 读取前四字节，写出源端口、目标端口和报文方向。
3. 按四字节边界读取 Seq 与 Ack，分别标注两个字节流方向。
4. 从 Data Offset 算出首部长度，再定位 Options 与 Payload 的分界。
5. 用 IP 层长度减去 IP 首部与 TCP 首部，得到 `tcp.len`。
6. 读取 Flags，判断这条记录承担数据传输还是连接控制职责。
7. 记录 Window 原始字段、Checksum 显示与选项列表，为后续上下文解释保留证据。

以样本执行这套流程，会得到“客户端 49152 发往服务端 9000、TCP 首部 32 字节、Payload 10 字节、ACK 与 PSH 置位”。这句话已经把方向、布局与报文职责浓缩成可继续分析的摘要。

## 在 Wireshark 中完成一次手工解析

### 实验步骤

1. 使用过滤器 `tcp.port == 9000 && tcp.len > 0` 选择一条数据报文。
2. 在 Packet Details 中收起所有协议树，只展开 Transmission Control Protocol。
3. 在 Packet Bytes 中找到 TCP 起点；IPv4 可用“链路层首部长度 + IHL”计算，IPv6则沿 Next Header 链逐项定位。
4. 从 TCP 起点抄录前 20 字节，按 2、2、4、4、2、2、2、2 字节切分。
5. 读取 Data Offset，计算完整 TCP 首部长度。
6. 使用 IP 层提供的总长度边界计算 TCP Payload 长度。
7. 将手工结果与 `tcp.srcport`、`tcp.dstport`、`tcp.seq_raw`、`tcp.ack_raw`、`tcp.hdr_len` 和 `tcp.len` 对照。

### 预期现象

- 源/目标端口可直接由前四字节得到。
- `tcp.seq_raw` 和 `tcp.ack_raw` 对应原始 32 位字段；界面主摘要可能显示相对值。
- TCP 首部大于 20 字节时，固定首部之后会出现 Options 节点。
- `tcp.len` 等于 IP 层载荷长度减 TCP 首部长度。
- 点击字段后，Packet Bytes 会高亮该字段占用的精确位或字节。

## 理解检查

1. TCP 起点后的第 12 字节为 `0x70`。Data Offset 是多少？TCP 首部有多少字节？选项区域有多少字节？
2. IPv4 Total Length 是 84 字节，IHL 是 5，TCP Data Offset 是 7。TCP Payload 长度是多少？
3. 报文由服务端 `9000` 发回客户端 `49152` 时，首部前四字节应怎样排列？
4. Wireshark 显示 `Seq = 1`，原始四字节为 `6a 1b 2c 3e`。哪一个值适合与十六进制帧逐字节核对？

<details>
<summary>参考答案</summary>

1. 高四位为 7，首部长度为 $7\times4=28$ 字节，选项区域为 $28-20=8$ 字节。
2. IPv4 首部为 $5\times4=20$ 字节，TCP 首部为 $7\times4=28$ 字节，所以 Payload 为 $84-20-28=36$ 字节。
3. 源端口 `9000 = 0x2328`，目标端口 `49152 = 0xc000`，所以前四字节为 `23 28 c0 00`。
4. 原始值 `0x6a1b2c3e` 可以与帧中的四字节直接核对；相对值 `1` 适合阅读连接进度。

</details>

## 本章小结

- TCP 固定首部为 20 字节，Data Offset 决定完整首部长度。
- 样本 Data Offset 为 8，完整首部为 32 字节，其中选项占 12 字节。
- 多字节整数采用网络字节序，先切字段再从高位到低位组合。
- TCP Payload 长度可以通过 IP 长度、IP 首部长度和 TCP 首部长度逐步相减得到。
- Seq 属于当前发送方向，Ack 与 Window描述反方向接收进度。
- 原始字节、协议解释、上下文解释、显示转换与分析器推断构成不同证据层次。
