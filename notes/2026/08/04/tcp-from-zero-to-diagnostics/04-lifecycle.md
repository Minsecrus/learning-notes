# 第四篇 TCP 连接的建立、状态和关闭

前三篇已经建立了字节流、四元组与 TCP 首部的基础。本篇把这些字段放回时间轴：一条连接怎样同步双方的序列号，两个端点为何处在不同状态，每个发送方向怎样独立结束，以及 FIN、TIME_WAIT、CLOSE_WAIT 与 RST 分别表达什么。

本篇继续使用 `127.0.0.1:18080` 上的受控 Python 程序。每个实验都保留四类证据：应用打印的 API 时刻、Windows 或 Linux 查询到的连接状态、Wireshark 捕获的线上报文、根据 Seq/Ack 作出的手工计算。回环通信速度很快，代码会通过暂停点把短暂状态留给观察。

## 贯穿全篇的双向模型

把一条连接画成两条单向字节流最为清晰：

```text
客户端发送方向  =============================>  服务端接收方向
客户端接收方向  <=============================  服务端发送方向
```

SYN 为两个方向建立序列号空间。FIN 只结束发送它的那个方向。RST 会中止整条连接。状态名则记录本端已经发送和收到哪些控制信息，因此同一时刻的客户端与服务端经常显示不同状态。

## 第四篇综合任务

完成五组时间线：正常建立、客户端主动半关闭、正常双向关闭、连接被拒绝、服务端强制重置。每组都从客户端和服务端分别记录：

1. 触发事件，例如 `connect`、`shutdown`、`close`、收到报文或计时器到期。
2. 事件前后的本地状态。
3. 报文的 Flags、Seq、Ack 与 TCP Payload 长度。
4. 应用观察到的返回值、EOF 或异常。

时间线中的每次迁移都应具有直接触发证据。Wireshark 的相对序列号适合阅读，涉及计算时需明确当前使用相对值还是首部中的绝对值。
