# 第一篇 TCP 基础直觉与通信模型

这一篇先建立整体地图。我们从一个 URL 出发，沿着域名解析、路由、链路传输、TCP 连接和应用请求逐层前进；随后观察 TCP 如何把有损的 IP 网络组织成双向有序字节流；最后亲手制造一次发送对应多次读取、几次发送合并为一次读取的现象。

## 学习目标

完成本篇后，你将能够：

- 说明域名、IP 地址、MAC 地址和端口各自的作用范围。
- 画出应用数据经 TCP、IP 和链路层封装后发往下一跳的过程。
- 解释序列号、确认、重传、接收窗口与拥塞控制怎样协作。
- 准确描述一次 `send` 与一次 `recv` 的关系。
- 使用长度字段为连续字节划分应用消息。

## 章节

1. [一次网络请求是怎样发生的](./01-foundations/01-network-request.md)：从 URL 到响应，建立完整通信路径。
2. [TCP 提供怎样的通信能力](./01-foundations/02-tcp-capabilities.md)：理解有序、可靠、全双工字节流背后的机制地图。
3. [TCP 是字节流](./01-foundations/03-byte-stream.md)：通过可重复实验理解读取边界，并实现长度前缀分帧。

## 本篇综合任务

请在读完三章后完成两张图：

1. 一张分层图，从应用消息画到 TCP 报文段、IP 数据报和链路层帧，并标出域名、IP、MAC、端口和 Socket 出现的位置。
2. 一张字节流图，假设发送方依次提交 `ABC`、`DE`、`FGHI`，画出至少三种合法的 `recv` 返回分组，同时保持最终字节序列完全一致。

图中的每条结论都注明证据层次。抓包能展示 TCP 报文，应用日志能展示消息处理结果，两者结合后形成完整解释。
