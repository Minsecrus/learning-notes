# 第二篇 认识一条 TCP 连接

第一篇建立了分层与字节流模型。从这一篇开始，我们把抽象概念落到三类可以亲手验证的对象上：Python 程序里的 Socket、操作系统维护的连接状态、Wireshark 捕获的 TCP 报文。

本篇围绕一条本机回环连接展开。服务端监听 `127.0.0.1:50007`，客户端由操作系统分配临时端口，双方交换一条带4字节长度字段的消息。三个章节会反复观察同一条连接，每次增加一种证据。

## 本篇完成后的能力

完成本篇后，你将能够：

- 根据本地地址、本地端口、远端地址和远端端口描述一个已连接 Socket；
- 区分监听 Socket 与 `accept` 返回的已连接 Socket；
- 准确说明 `bind`、`listen`、`accept`、`connect`、`sendall`、`recv` 和 `close` 在程序中的作用；
- 用 `Get-NetTCPConnection` 将程序对象对应到操作系统连接状态；
- 在 Windows 回环接口上捕获连接建立、数据交换与连接关闭；
- 用 `tcp.stream`、四元组和日志时间定位自己的流量。

## 统一实验约定

- 仅依赖 Python 3 标准库，环境准备保持轻量。
- 使用 `127.0.0.1` 固定走 IPv4 回环路径。
- 使用 TCP 端口 `50007`；若该端口已被占用，可以在客户端和服务端中同步替换为同一个空闲端口。
- PowerShell 命令采用 `python -X utf8`，确保中文日志采用 UTF-8。
- 抓包使用 Wireshark 与 Npcap 提供的回环接口。
- 每次实验记录客户端日志、服务端日志、系统连接表和抓包；四类证据共同组成一条可复核时间线。

这一篇暂时只处理单次请求—响应。多消息循环、超时、并发服务、背压以及更完整的错误处理会在第六篇逐步加入。

## 第二篇综合任务

提交一份能够复核完整连接过程的实验记录，内容包括：

1. 第5章的最小客户端与服务端程序，并标明实际使用的地址和端口。
2. 客户端日志与服务端日志，保留关键 Socket API 调用、返回值、端点和时间戳。
3. 连接存续期间的系统连接状态，记录 `LISTEN` 与 `ESTABLISHED` 条目。
4. 从建立连接到释放连接的抓包文件，以及只显示目标 `tcp.stream` 的关键报文截图或表格。

在四元组表中，把监听 Socket 记录为本地监听端点与未指定的远端端点，把 `accept` 返回的已连接 Socket 记录为完整四元组。若同时运行多个客户端，为每条连接单独记录客户端临时端口，从而说明它们如何共享服务端端口。

最后按时间顺序对齐两端日志、系统状态与抓包，逐项解释 `connect`、`accept`、`sendall`、`recv`、`close` 等关键 API，以及 SYN、SYN+ACK、ACK、数据、FIN 或 RST 等关键报文。对齐时注明每项内容属于程序日志、系统状态、线上报文或分析器推断，使整条解释可以沿证据回查。
