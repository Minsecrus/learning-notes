# TCP 从入门到抓包诊断

TCP 隐藏了丢包、乱序、重复、路径容量变化等网络细节，让应用看到一条可靠、有序、全双工的字节流。这个抽象很强，也带来了新的学习任务：应用需要自己定义消息边界，开发者需要理解部分读写和关闭语义，排障时还要把程序日志、Socket 状态、TCP 报文和网络路径连接成同一条证据链。

本教程从一个本地 Python 客户端与服务端开始。读者会亲手建立连接、连续发送消息、设计长度前缀协议、抓取握手与关闭过程，再逐步制造延迟、丢包、零窗口、RST、慢客户端和 MTU 问题。全书最终落到一个可以运行、可以抓包、可以诊断的请求—响应消息服务。

## 学完以后能够做什么

完成全系列后，你将能够：

1. 从浏览器、应用进程、Socket、TCP、IP 和链路层六个视角解释一次网络通信；
2. 用四元组识别连接，用 Seq、Ack、Flags、Window 和 Options 阅读 TCP 报文；
3. 写出正确处理消息边界、部分读写、EOF、超时、重试、幂等和背压的程序；
4. 区分流量控制与拥塞控制，计算 MSS、窗口和带宽时延积；
5. 识别抓包卸载、捕获缺失和分析器推断造成的观察差异；
6. 对连接超时、RST、CLOSE_WAIT、TIME_WAIT、零窗口、重传和低吞吐形成可验证的诊断结论；
7. 理解 NAT、防火墙、代理、负载均衡、TLS、HTTP 与 QUIC 对连接路径的影响。

## 一条贯穿全书的实验主线

教程持续扩展同一个消息服务：

```mermaid
flowchart LR
  A["最小 TCP 回显"] --> B["长度前缀分帧"]
  B --> C["请求 ID 与错误响应"]
  C --> D["超时、重试与幂等"]
  D --> E["并发、队列与背压"]
  E --> F["TLS 加密"]
  F --> G["故障注入与抓包诊断"]
```

每个阶段都保留四类证据：

- 客户端日志记录调用、返回值、请求 ID 和时间；
- 服务端日志记录接受连接、读取、业务处理与关闭；
- 系统命令记录监听端点、四元组和 TCP 状态；
- Wireshark 或 tcpdump 记录线上可观察的报文。

这四类证据会互相补充。应用日志回答业务执行情况，Socket 返回值描述进程与内核的交互，系统状态呈现协议栈当前记录，抓包呈现特定观察点经过的数据。

## 实验平台

主线代码使用 Python 标准库 `socket`，主线桌面环境使用 Windows PowerShell 与 Wireshark/Npcap。基础程序同时适用于 Linux 和 macOS。延迟、丢包、乱序、带宽与 MTU 故障注入使用受控的 Linux、WSL 或虚拟机环境；每个相关章节也会提供只读抓包或替代观察方法。

实验统一从回环地址开始：

- IPv4：`127.0.0.1`
- IPv6：`::1`
- 附录命令占位端口：`5000`；各篇实验以篇入口约定的端口为准

端口可以通过命令行参数调整。运行前先检查占用情况，结束后关闭客户端、服务端和抓包任务。

## 阅读中的六个层次

TCP 问题经常横跨多个层次。全书统一使用下面的分类：

| 层次 | 典型问题 |
| --- | --- |
| 应用语义 | 请求是否成功，数据是否持久化，重试是否会重复执行 |
| Socket API | `send` 接受了多少字节，`recv` 为什么返回长度为0的结果，调用为何超时 |
| TCP 协议 | Seq/Ack 怎样推进，窗口怎样变化，连接处于什么状态 |
| 操作系统实现 | 缓冲区、队列、计时器、拥塞算法和卸载怎样工作 |
| 抓包事实 | 某个接口、某个时刻实际捕获到了哪些帧和报文段 |
| 分析器推断 | Wireshark 怎样标注重传、乱序、重复 ACK 和窗口事件 |

分析时先确定问题所属层次，再寻找能够直接支持结论的证据。跨层推断需要额外验证，例如 TCP ACK 可以证明对端协议栈接收了连续字节，业务成功还需要响应、状态查询或服务端记录。

## 学习成果的判断方式

每篇末尾都有综合任务。完成任务时，重点检查解释能否经受以下追问：

- 这个结论来自规范、实现文档、程序日志还是抓包？
- 抓包点在哪里，是否可能缺失帧或受到卸载影响？
- 数字怎样算出，单位是否一致？
- 同一种现象还有哪些可能原因？
- 哪个最小实验能够区分这些原因？

能够清楚回答这些问题，说明你已经把知识转化为可操作的分析能力。
